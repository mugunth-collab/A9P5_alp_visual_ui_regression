# A9P5 - An Automated Visual Regression Detection Framework for Identifying UI Defects Across Heterogeneous Mobile Devices and Display Configurations

**Track:** Track 5  
**Application:** ML-based UI defect detection across heterogeneous devices

This dataset is synthetic, generated by gen_author9.py with seed 2121. It must be described as synthetic in any publication.

## Simulated scenario

A mobile team captures baseline vs candidate screenshots per build across device tiers, font scales, dark mode, RTL locales and orientations. Each row is one comparison with display configuration, what the build changed, and extracted visual-diff features. Many diffs are harmless (dynamic content, animations, rendering noise); the label marks human-confirmed defects and their type.

## How it was generated

Defects (~11%) arise from interactions such as layout change x large fonts, string change x RTL/2x font, style change x dark mode, layout change x foldables / narrow screens / landscape. Pixel diff and SSIM are dominated by dynamic content and animation (so naive pixel thresholds produce false alarms), while defect-type-specific features (overflow, overlaps, alignment, contrast drop, missing elements) carry the signal.

Realism noise common to all numeric signals: ~5% multiplicative Gaussian measurement noise, 1-3% missing values in a few columns (empty cells), and ~0.5-1% injected outliers (listed per table below). Targets were computed from the noise-free latent signals, so the observed features are imperfect proxies.

## Suggested experiments

1. Defect detection: pixel_diff threshold baseline vs SSIM threshold vs GBM on all features; report F1, precision at 90% recall, false alarms per build.
2. Defect type classification (macro-F1) for triage routing.
3. Cross-device generalisation: train on phones, test on foldables/tablets; report F1 drop.
4. Configuration-aware test selection: predict which device/config combos are likely to show defects for a build; recall vs number of screenshots captured.
